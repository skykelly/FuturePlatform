# 부록 A. 검토 방법

> [[Portfolio]]의 부속 문서입니다. 9개 플랫폼 기회를 도출하고 선정한 절차와 기준을 정리했습니다.

## 후보 도출 절차 (Platform Ideation Genome v3)

| 단계 | 검토 내용 | 예시 |
|---|---|---|
| 1. 구조 변화 | 10년 후 산업의 역할 분담을 바꿀 변화 | AI 에이전트의 구매 대행, 가사 인력 감소, 고령화 |
| 2. 새로운 고객 과제 | 변화로 인해 새로 생기는 고객 요구 | 건물주는 개별 설비보다 공간 가동률을 원함 |
| 3. LG 고유 자산 | LG만 가진 자산의 조합 | 설치 기반, A/S망, 수리 이력, 구독 |
| 4. 시장 실패 | 현재 시장이 해결하지 못하는 이유 | 중고 가전 상태를 보증하는 주체가 없음 |
| 5. 확보할 위치 | LG가 결정·허용·거절할 수 있는 영역과 그 근거가 되는 책임 | 작업 결과를 보증하므로 투입 로봇을 결정 |
| 6. 사업 방식 | 시장 확장 방식 | 아래 표 참조 |
| 7. 성장 구조와 방어력 | 규모가 커질수록 가치가 커지는 구조, 축적되는 자산 | 진단할수록 쌓이는 집 상태 데이터 |

## 플랫폼 성립 요건

| 요건 | 확인 질문 | LG 예시 |
|---|---|---|
| 접근권 | 고객·공간·기기에 지속적으로 접근할 수 있는가 | 정기 방문 계약, 설비 원격 접속, 설치 기반 |
| 판단권 | 판단에 필요한 정보와 권한이 있는가 | 제조 이력, 고장 이력, 센서 데이터 |
| 거절권 | 공급자·서비스를 선택하거나 배제할 수 있는가 | 이 요건이 없으면 플랫폼이 아닌 인프라로 분류 |

거절권은 결과에 대한 책임에서 생깁니다. 결과를 보증하는 사업자는 품질 관리를 위해 하위 공급자를 선택·배제해야 하고, 이 권한이 플랫폼 사업의 기반이 됩니다. LG는 사람을 보내고, 수리하고, 보증할 수 있다는 점에서 소프트웨어 기업과 차별화됩니다.

## 사업 방식 5가지

| 사업 방식 | 내용 | 적용 기회 |
|---|---|---|
| 실행 계층 (Runtime) | 타사 기기·로봇·AI가 거쳐야 하는 운영 계층 확보 | PF-02, PF-03, PF-06 |
| 수요 집약 (Aggregation) | 분산된 수요를 모아 공급자 협상력 확보 | PF-01, PF-05, PF-07 |
| 중개 (Marketplace) | 진단·보증으로 확정된 수요를 공급자와 연결 | PF-06, PF-07, PF-09 |
| 표준·인증 (Standard) | 등급·인증·규격을 정의해 가격과 채택에 영향 | PF-02, PF-08, PF-09 |
| 유통 (Distribution) | 서비스 노출 순서와 시점 결정 | PF-04 |

## 선정 기준

통과 기준 6가지를 모두 충족해야 합니다.

1. LG가 빠지면 시장 참여자의 행동이 달라지는가
2. 경쟁사보다 유리한 출발점이 있는가
3. LG가 이 위치를 맡는 것이 산업 구조상 자연스러운가
4. 규모가 커질수록 가치가 커지는 구조가 있는가
5. 외부 참여자가 들어올 이유가 있는가
6. 다른 후보의 하위 기능이 아닌가

다음 중 하나라도 해당하면 제외했습니다.

| 제외 기준 | 내용 |
|---|---|
| 확보할 위치 없음 | 데이터 제공이나 사용성 개선만으로는 플랫폼이 아님 |
| LG 자격 없음 | 관련 자산이 없거나 브랜드·규제상 부적합 |
| 자기잠식 | 기존 사업 손익을 직접 훼손 |
| 중복 | 다른 후보의 하위 기능 |
| 범위 이탈 | 담당 소관 또는 검토 범위 밖 |

시장 규모가 가장 컸던 Physical World Data Trust(가정 데이터 거래)는 고객 신뢰를 낮은 수익과 맞바꾸는 구조여서 다른 사업의 기반을 훼손한다고 판단해 제외했습니다.

## 후보 수렴 과정

| 주요 주제 | 에이전트 커머스, Physical AI, 자율 공간, 앰비언트 컴퓨팅, 에너지 전환, 모빌리티 | 에이전트 구매, 가사 인력 감소, 고령화, 공간 재편, 제품 수명 연장, 현장 지식 소멸 |

|---|:-:|---|

가장 많이 적용된 제외 사유는 중복입니다. 가정 영역 후보 상당수가 "고객 집에 정기적으로 들어갈 수 있는 신뢰"라는 같은 위치로 수렴했습니다.

- 통합: Route A의 Autonomous Building OS와 Route B의 Commercial Space OS는 건물 운영 결과를 책임진다는 점이 같아 PF-03으로 통합했습니다.
- 분리 유지: PF-02와 PF-06은 모두 로봇을 다루지만 고객이 다릅니다. PF-02는 로봇 제조사와 AI 개발자, PF-06은 건물·매장·호텔 운영자가 고객이므로 별도 기회로 유지했습니다.
